# Trustworthy AI Hackathon：政府服務 Demo 差距分析

## 一句話定位

把「你不申請就不給」改成「你只要授權一次，可信 Agent 就能跨機關找資格、備妥申請，並在高風險送件前交還控制權」。

## 比賽真正評分什麼

| 評分項目 | 比重 | 對本 Demo 的含義 |
|---|---:|---|
| 產業應用場景契合度 | 35% | 必須直接解決重複申辦、跨機關資料孤島與期限遺漏，而非只展示聊天能力。 |
| 可信技術導入可行性 | 25% | 要把身分、憑證、揭露控制、授權、撤銷與問責做成可操作流程。 |
| 簡報與 Demo 呈現 | 25% | 只有 5 分鐘且全程播放錄影，所有主張都要在畫面中被證明。 |
| 問題洞察與創意 | 15% | 要說清楚為何不能只做 API Gateway，以及 AI Agent 補上 MyData／數位皮夾尚未解決的代理缺口。 |

來源：`比賽規範說明簡報.pptx.pdf` p.5–7；`痛點4_政府服務_Jim Lin_20260822.pdf` p.5–7。

## 必須回答的六個信任要點

政府題目明確表示 Demo Day 評審會看：

1. **Principal**：Agent 代表哪位民眾或家戶。
2. **Authorization**：代查、代填、代送分別授權到什麼程度。
3. **Tool / Action**：Agent 可以呼叫哪些工具，能否跨機關比對憑證。
4. **Policy Gate**：哪些高風險操作必須本人再次確認。
5. **Audit Log**：能否還原查了什麼、依據什麼、填了什麼。
6. **Expiry / Revocation**：委託是否會到期，撤銷後是否立即停止。

來源：`痛點4_政府服務_Jim Lin_20260822.pdf` p.8；`0822_產業工作坊_場片.pdf` p.15、p.27。

## 現有 Demo 評估

| 面向 | 現況 | 判定 |
|---|---|---|
| 真實痛點 | 支援跨機關服務發現、資格檢查、申請與案件查詢 | 已具備 |
| Principal | Session 綁定單一 Mock citizen | 部分具備；尚未明示本人／家戶界線 |
| Authorization | 有用途說明與同意／拒絕 | 部分具備；不是可驗證、可到期的委託憑證 |
| Tool / Action | Model 只能選擇後端允許的結構化行動 | 已具備 |
| Policy Gate | 帳戶與送件前要求本人確認 | 已具備 |
| Audit Log | 畫面顯示時間、行動與摘要 | 部分具備；仍是記憶體紀錄，未防竄改／匯出 |
| Revocation | 前端舊原型有概念，但目前後端流程沒有撤銷 action | 缺少 |
| 憑證驗證 | Government Data Adapter 回傳最小化證據 | 部分具備；尚無簽章、issuer key、expiry、status |
| 主動提醒 | 目前由民眾先提問 | 缺少 |
| 多機關轉換 | 可查不同機關證據 | 部分具備；尚未展示滿 2 歲跨部會自動轉換 |
| 合成資料 | 全部為 Mock Data | 已符合紅線 |
| 部署 | GitHub、Docker、Zeabur 支援 | 已具備 |

## P0：為了進決選／拚冠軍必須完成

### 1. 可驗證的「民眾委託 Agent」憑證

畫面要能展開一張委託憑證：

```json
{
  "principal": "citizen-demo-001",
  "agent": "did:web:gov.example:benefit-agent",
  "service": "childcare-benefit-2026",
  "actions": ["read_evidence", "prepare_application"],
  "requiresHumanConfirmation": ["submit_application", "change_bank_account"],
  "validUntil": "2026-08-29T13:30:00+08:00",
  "status": "active"
}
```

至少展示 issuer、subject、scope、expiry、signature/status；否則目前只是 UI 狀態，不足以佐證「可信技術」。

來源：`痛點4_政府服務_Jim Lin_20260822.pdf` p.7–9。

### 2. 後端即時撤銷

Demo 中按下「撤銷委託」，再讓 Agent 嘗試讀取資料或送件，後端必須拒絕並在 Audit Log 顯示原因。這是最容易被評審看懂的可信技術證明。

來源：`痛點4_政府服務_Jim Lin_20260822.pdf` p.8–9；`0822_產業工作坊_場片.pdf` p.15、p.27。

### 3. Agent 身分與工具權限

目前頁面寫「已驗證 Agent」，但尚無實際證明。應顯示政府機關簽發的 Agent Manifest：

- Agent 代表哪個機關。
- 允許使用哪些工具。
- 禁止核准補助、修改戶籍、未確認送件。
- 憑證何時到期／是否撤銷。

### 4. 可驗證政府證據卡

每項 evidence 顯示：

- 發證機關。
- 最小揭露結果。
- 簽章驗證。
- 有效期限／資料新鮮度。
- 撤銷狀態。
- 哪條政策規則使用了它。

避免只顯示「available」，否則難以拿到可信技術分數。

### 5. 完成交件資產

- 五分鐘 Demo 錄影。
- Demo Day 簡報。
- GitHub repo 與 README。
- Demo 連結。
- 一頁 Governance Gap Memo。

規範文件稱只繳交簡報，但政府題目文件另列 repo、簡報、Demo 連結／影片、Memo、README；應採較嚴格集合全部準備，並向主辦確認實際上傳方式。

來源：`比賽規範說明簡報.pptx.pdf` p.4–6；`痛點4_政府服務_Jim Lin_20260822.pdf` p.10。

## P1：最能拉開差距

### 1. 主動式提醒

模擬「孩子滿 2 歲前 30 天」事件：

1. Agent 主動通知育兒津貼即將轉換主管機關。
2. 列出已具備的證據與缺少項目。
3. 自動建立下一階段草稿。
4. 民眾只需確認。

這直接對應題目建議，且比單純聊天更有故事性。

來源：`痛點4_政府服務_Jim Lin_20260822.pdf` p.2–3、p.9。

### 2. 家戶／多人授權

明確定義目前 Agent 只代表申請人；若服務需要配偶或其他家人資料，顯示「等待第二位家戶成員授權」，避免把一人的授權擴張成整個家戶。

來源：`痛點4_政府服務_Jim Lin_20260822.pdf` p.8。

### 3. 防竄改 Audit Bundle

匯出一份申請證明：

- 使用的 evidence IDs。
- 規則版本。
- Model 建議與後端執行 action。
- 本人確認時間。
- 每筆 audit entry 的 hash chain。

### 4. 可量化價值

Demo 結尾顯示：

- 從 4 次申辦降到 1 次授權＋1 次確認。
- 從 4 個網站降到單一 Agent。
- 重複填寫欄位數。
- 避免錯過 15 日期限。

來源：`痛點4_政府服務_Jim Lin_20260822.pdf` p.2–3。

## P2：呈現加分

- 多語言與無障礙模式。
- 「為什麼需要這項資料」逐項解釋。
- 服務政策來源與規則版本連結。
- 案件補件提醒與一鍵準備附件。
- 以 MyData／數位憑證皮夾／Agent 三層圖說明定位。

## 建議五分鐘 Demo 腳本

### 0:00–0:35｜痛點

用一張圖呈現媽媽因孩子年齡、搬家、送托而四次申辦；指出政府已有資料，但法律上不能任意跨目的打通。

### 0:35–1:10｜Agent 身分

打開 Agent Manifest：由哪個政府機關授權、可呼叫哪些工具、禁止哪些行動。

### 1:10–1:50｜主動發現

民眾說「我剛生小孩」，Agent 列出三項服務與 15 日期限；選擇育兒生活補助。

### 1:50–2:30｜可驗證委託

顯示委託憑證的 scope、expiry、最小揭露與「送件需本人確認」。民眾同意。

### 2:30–3:15｜跨機關資格比對

逐張顯示戶政、稅務、社福 evidence 的 issuer、signature、status；Policy Engine 解釋使用哪條規則。

### 3:15–3:50｜Policy Gate

Agent 建立草稿並要求選擇帳戶；本人確認後才送件，產生案件編號。

### 3:50–4:25｜撤銷攻擊

民眾撤銷委託，再要求 Agent 送另一件申請；後端立即阻擋，Audit Log 顯示 `authorization_revoked`。

### 4:25–5:00｜主動轉換與價值

快轉到孩子滿 2 歲前 30 天，Agent 主動準備跨部會轉換草稿。以「四次申辦 → 一次授權、必要時確認」收尾。

## 交件與展示風險

- Demo Day 不接受現場實機，必須把成功路徑、撤銷失敗路徑與 Audit Log 全部錄進影片。
- 超過五分鐘部分不計分。
- 評審不會預讀文件，因此憑證與治理設計必須直接出現在畫面。
- 不得使用真實醫療、金融或政府資料；目前 Mock Data 方向正確。
- 簡報需揭露開源專案、既有程式碼與 AI 生成內容。
